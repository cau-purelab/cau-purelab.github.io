# 검색 등록 · 방문 분석 — 사람이 직접 할 작업

`https://pure.cau.ac.kr/`가 구글·네이버 등에서 검색되고, 구글 애널리틱스(GA4)로 방문 기록을 볼 수 있게 하기 위해
**계정 로그인이 필요해서 코드로 대신할 수 없는 작업**만 모은 문서다. (작성 2026-11-06)

코드 쪽(사이트맵·robots.txt·구조화 데이터·본문 프리렌더·한국어 메타)은 이미 되어 있거나 저장소에서 처리한다.
아래 작업 중 **값을 발급받는 단계(★)** 가 끝나면 그 값을 개발 담당에게 넘기면 된다.

| 순서 | 작업 | 누가 | 넘겨줄 값 |
|---|---|---|---|
| 1 | 네이버 서치어드바이저 등록 | 연구실 네이버 계정 보유자 | ★ `naver-site-verification` 토큰 |
| 2 | 구글 Search Console 확인·사이트맵 제출 | 기존 소유 확인 계정 보유자 | (새로 발급한 경우만) 토큰 |
| 3 | 구글 애널리틱스(GA4) 설정 | 연구실 구글 계정 | ~~측정 ID~~ 전달 완료(`G-G6810EMH75`, 2026-11-06 사이트 적용) |
| 4 | 외부 사이트에 홈페이지 링크 걸기 | 교수님 / 학과 담당자 | 없음 |
| 5 | (선택) Bing · 다음 등록 | 누구나 | 없음 |

## 1. 네이버 서치어드바이저

1. https://searchadvisor.naver.com 접속 → 연구실 네이버 계정으로 로그인 → 우측 상단 **웹마스터 도구**.
2. 사이트 등록 칸에 `https://pure.cau.ac.kr` 입력 → 등록.
3. 소유확인 방법에서 **HTML 태그** 선택. 다음과 같은 태그가 나온다.
   ```html
   <meta name="naver-site-verification" content="abcdef0123456789..." />
   ```
   ★ **`content` 안의 값만** 복사해 개발 담당에게 전달한다. (이 화면은 닫지 말고 둔다)
4. 개발 담당이 태그를 넣고 배포했다고 알려 주면(1~2분 소요) **소유확인** 버튼을 누른다.
5. 소유확인이 끝나면 사이트를 눌러 관리 화면으로 들어가서:
   - **요청 → 사이트맵 제출**: `https://pure.cau.ac.kr/sitemap.xml`
   - **요청 → RSS 제출**: `https://pure.cau.ac.kr/feed.xml` (뉴스가 올라오면 네이버가 빨리 가져간다)
   - **요청 → 웹 페이지 수집**: 아래 6개를 하나씩 입력
     ```
     https://pure.cau.ac.kr/
     https://pure.cau.ac.kr/research
     https://pure.cau.ac.kr/people
     https://pure.cau.ac.kr/publications
     https://pure.cau.ac.kr/scholar
     https://pure.cau.ac.kr/news
     ```
   - **검증 → robots.txt** 에서 "수집 가능" 확인, **검증 → 사이트 간단 체크** 실행.
6. 반영까지 보통 **1~4주**. **리포트 → 검색 반영**에서 수집·노출 추이를 본다.

## 2. 구글 Search Console

소유 확인 태그(`index.html`)와 확인 파일(`googled74444b38c6d2830.html`)은 이미 배포되어 있다.

1. https://search.google.com/search-console 접속 → 예전에 소유 확인을 했던 구글 계정으로 로그인.
2. 왼쪽 위 속성 선택 목록에 **`https://pure.cau.ac.kr/`** 가 있는지 본다.
   - 없고 `cau-purelab.github.io`만 있다면: **속성 추가 → URL 접두어 → `https://pure.cau.ac.kr/`**
     → 확인 방법 **HTML 태그** 또는 **HTML 파일** 선택 → 바로 확인되면 끝.
   - 확인이 안 되고 새 토큰이 나오면 그 값을 개발 담당에게 전달.
3. **Sitemaps** 메뉴 → `sitemap.xml` 입력 → 제출. 상태가 "성공"이 되는지 확인.
4. 상단 **URL 검사**에 1-5의 6개 주소를 하나씩 넣고 **색인 생성 요청**.
5. 며칠~2주 뒤 구글에서 `site:pure.cau.ac.kr` 검색, 또는 **페이지** 보고서로 색인 상태 확인.
6. 다른 연구실원도 보게 하려면 **설정 → 사용자 및 권한 → 사용자 추가**(권한: 제한됨).

## 3. 구글 애널리틱스(GA4)

1. https://analytics.google.com 접속 → 연구실 구글 계정으로 로그인 → **측정 시작**(또는 **관리 → 만들기 → 계정**).
   - 계정 이름: `PURE Lab`
   - 속성 이름: `pure.cau.ac.kr`, 시간대 **대한민국**, 통화 **KRW**
   - 비즈니스 정보는 아무거나(교육/소규모) 선택해도 된다.
2. 플랫폼 **웹** 선택 → 웹사이트 URL `https://pure.cau.ac.kr`, 스트림 이름 `PURE homepage`.
3. 생성된 스트림 화면 오른쪽 위의 ★ **측정 ID(`G-`로 시작)** 를 개발 담당에게 전달.
   → ✅ 완료: `G-G6810EMH75`가 사이트에 들어가 있다(`src/constants.tsx`의 `GA_MEASUREMENT_ID`).
   "Google 태그 설치 안내" 코드는 붙이지 않는다 — `src/lib/analytics.ts`가 같은 일을 정식 도메인에서만 한다.
4. ⚠ **필수**: 같은 스트림 화면의 **향상된 측정** 톱니바퀴를 눌러
   **"브라우저 기록 이벤트 기반 페이지 변경"을 끈다**(기본값은 켜짐). 향상된 측정 자체는 켜 둔다.
   → 이 사이트는 페이지를 옮길 때마다 코드가 직접 page_view를 보낸다(탭 제목이 늦게 바뀌는 문제를 피하려고).
   이 옵션이 켜져 있으면 GA도 따로 한 번 더 보내 **페이지 이동이 2번씩 집계된다**.
   → ✅ 2026-11-06 끔(화면 위치: 향상된 측정 → **페이지 조회 → 고급 설정 표시** → "브라우저 방문 기록 이벤트 기반 페이지 변경" 체크 해제). 실시간 보고서에서 이동당 1건 확인.
   - 선택: 같은 화면의 **"양식 상호작용"** 은 Publication Archive 검색창을 쓸 때마다 `form_start`를 남긴다. 필요 없으면 끈다.
5. 권장 설정 (관리 메뉴):
   - **데이터 수집 및 수정 → 데이터 보존 → 14개월** (기본 2개월이라 연간 비교가 안 된다)
   - **데이터 스트림 → 태그 설정 더보기 → 내부 트래픽 정의**에 연구실 공인 IP를 등록하고,
     **데이터 필터**에서 "Internal Traffic" 필터를 **활성**으로 바꾼다 (연구실원 접속 제외).
     공인 IP는 연구실 PC에서 "내 IP"를 검색하면 나온다.
   - **제품 링크 → Search Console 링크** → 2절의 속성 연결 (어떤 검색어로 들어왔는지 GA에서 보인다)
   - **속성 액세스 관리**에 교수님·연구실원 계정을 **뷰어**로 추가
6. 개발 담당이 배포했다고 알려 주면 **보고서 → 실시간**을 열어 둔 채 사이트를 몇 페이지 이동해 보고,
   페이지 이동이 각각 집계되는지 확인한다(1분 내 표시).

> 개인정보 안내: GA는 쿠키로 방문자를 구분한다. 개발 담당이 푸터에
> "방문 통계를 위해 Google Analytics를 사용합니다" 문구를 넣을 수 있다 — 넣을지 연구실에서 정해 줄 것.
